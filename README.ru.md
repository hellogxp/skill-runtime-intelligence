Agent Skill Runtime Intelligence — это система свидетельств и диагностики навыков агента, доступная только для чтения. Он объединяет определения навыков, официальные события времени выполнения агента, импортированные трассировки, резервный сеанс сеанса и наблюдаемые результаты рабочей области в уровень Skill Run Panorama с уровнем доказательности.

![Skill Run Panorama](docs/assets/skill-run-panorama.png)

## Быстрый старт

Установите и запустите последнюю версию на macOS или Linux:

```bash
curl -LsSf https://raw.githubusercontent.com/hellogxp/skill-runtime-intelligence/main/scripts/install.sh | sh -s -- --start
```

Никакого клона, учетной записи, `sudo` или GitHub CLI не требуется. Установщик проверяет контрольную сумму выпуска, обнаруживает поддерживаемые агенты и навыки, объясняет каждый путь, который он будет читать, запрашивает один раз, прежде чем включать перехватчики только для наблюдения, и открывает локальный UI в [http://127.0.0.1:4317](http://127.0.0.1:4317). Данные времени выполнения остаются под `~/.skill-runtime`, если вы явно не настроите экспорт.

Вы можете нажать [проверить установщик](scripts/install.sh) перед запуском.

### Смотрите свой первый прямой эфир SkillRun

1. Примите дополнительную настройку отказооткрытия Hook по запросу установщика.
2. Перезапустите агент и начните новую задачу. В Codex сначала просмотрите управляемые команды в `/hooks`; существующие задачи не загружают новые Hook в горячем режиме.
3. Используйте навык как обычно, затем подтвердите интеграцию и откройте UI:

```bash
skill-runtime doctor
skill-runtime status
```

Интеграция становится **действующей** только после того, как Collector получит реальное событие времени выполнения. Настроенный, но не наблюдаемый Hook находится в статусе **Ожидание** и никогда не представляется в качестве реального доказательства. Откройте [http://127.0.0.1:4317](http://127.0.0.1:4317) или просмотрите [Руководство по началу работы](docs/getting-started.md) для получения инструкций и устранения неполадок для конкретного агента.

Чтобы запустить непосредственно из исходного оформления:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/skill-runtime install --enable-hooks
.venv/bin/skill-runtime start
```

| Поверхность продукта | Что это отвечает |
|---|---|
| Runtime Overview | Какие SkillRuns требуют внимания? |
| First Observable Boundary | Где доказательства впервые пропали или оказались недействительными? |
| Skill Run Panorama | Как связаны запрос, активация, ресурсы, инструменты, артефакты и результат? |
| Evidence Inspector | Какой источник, класс, основа и возможности адаптера подтверждают это утверждение? |
| Сравнивать | Является ли разница поведенческой или только наблюдаемой? |
| Inferred Analysis | Какое обоснованное объяснение или следующее расследование является правдоподобным? |
| Настройки/Доктор | Что читается, сохраняется, экспортируется, ожидает и проверяется? |

## Как это работает

![Runtime architecture](docs/assets/runtime-architecture.svg)

Skill Runtime наблюдает за рабочим процессом, который вы уже используете. Адаптеры с поддержкой версий превращают собственные события агента в стабильный жизненный цикл навыка, в то время как исходные конверты, нормализованные события, связи и выводы остаются отдельными. Механизм диагностики сначала определяет самую раннюю границу, где доказательства отсутствуют или недействительны; он не изобретает модель намерения или причинной эффективности.

| Источник данных | Роль | Свежесть | Метка UI |
|---|---|---|---|
| Официальные агентские хуки/плагины/события SDK | Первичный жизненный цикл, инструмент, субагент и терминальное свидетельство | Жить | `Official hook` / `Native telemetry` |
| Файлы навыков и наблюдаемые результаты рабочего пространства | Определение, ресурс, файл, артефакт и свидетельство теста | Живой снимок/индексированный | `Observed` |
| Стенограммы сеансов | Резервный вариант совместимости, когда агент не предоставляет достаточного времени выполнения API | Почти живой или исторический | `Transcript fallback` |
| OTLP и поддерживаемый экспорт трассировки | Функциональная совместимость и исторический смысл | Живой экспорт/пакетный импорт | Показан исходный профиль |
| Детерминированная корреляция | Связывает события с SkillRun без изменения исходных фактов. | При проглатывании | `Derived` |
| Семантическая помощь | Только пояснения и предложения по расследованию. | По требованию | `Inferred` |

Поддерживаемые адаптеры сторонних производителей имеют независимые версии:

| Агент | Первичная интеграция | Отступать | Видимость активации |
|---|---|---|---|
| Codex | Официальная команда Hooks | Импорт сеанса | Явная активация при воздействии события Hook |
| Claude Code | Официальные Hooks | Импорт сеанса | Инструмент «Явные навыки» и доказательства слэш-команды, где они обнаружены |
| Qoder | Официальная команда Hooks | Местные записи | Явная активация при открытии с помощью инструмента Skill. |
| OpenCode | Глобальный плагин только для наблюдения | Местные записи | Обратные вызовы инструментов навыков, где они доступны |

Точные пределы возможностей описаны в файле [Матрица возможностей адаптера](docs/adapter-capability-matrix.md). Неподдерживаемые и ненаблюдаемые этапы остаются видимыми, а не превращаются в сбои.

## Проблема

Установка навыка не доказывает, что агент обнаружил его. Обнаружение не доказывает активацию. Активация не доказывает, что были загружены полные инструкции и ресурсы. Исполнение не доказывает, что Навык улучшил результат.

Сегодня эти неудачи часто замалчиваются. Разработчикам остается спросить:

- Был ли навык доступен этому агенту?
- Активировалось ли оно по этому запросу?
- Какие инструкции, ссылки, сценарии и ресурсы были загружены?
- Какие инструменты, вызовы MCP, субагенты, файлы и артефакты были задействованы?
- Где произошел сбой выполнения, повторная попытка или потеря контекста?
- Помог ли Навык или он только увеличил стоимость и задержку?

## Диагностика навыков

Первичным диагностическим объектом является `SkillRun`, а не весь сеанс агента:

```text
User request
    ↓
Skills discovered
    ↓
Skill selected / not selected
    ↓
SKILL.md activated
    ↓
References and scripts loaded
    ↓
Tools / MCP / subagents executed
    ↓
Files and artifacts produced
    ↓
Observable outcome
```

UI обеспечивает упорядоченность, типизацию и степень достоверности жизненного цикла. Отсутствие телеметрии активации означает «не наблюдается» или «не поддерживается»; это не означает, что Агент определенно пропустил Навык.

## Доказательная дисциплина

UI никогда не должен представлять вывод как факт времени выполнения:

- **Наблюдается** — явно присутствует в исходном событии или файле.
- **Производное** — детерминировано связанное с наблюдаемыми данными.
- **Предполагаемое** — правдоподобное объяснение с неопределенностью.
- **Экспериментальный** — эффект, измеренный посредством контролируемой парной оценки.

Одна трассировка может поддерживать атрибуцию выполнения. Он не может доказать причинную эффективность. Заявления типа «этот навык улучшил вероятность успеха» требуют повторной оценки с использованием навыка или без него.

## Принципы продукта

- По умолчанию частный, с локальным, гибридным и групповым развертыванием.
- Наблюдение только для чтения; никогда не берите на себя цикл агента.
- Никакого модельного прокси и обязательного облачного сервиса.
- В продукте по умолчанию нет блокировки, шлюза утверждения или применения политик.
- Явное происхождение и классификация доказательств.
- Постепенное раскрытие: сначала простое повествование, необработанные события по запросу.
- Поддержка изменения форматов расшифровок агентов на основе адаптера.

## Текущий объем

Среда выполнения поддерживает Codex, Claude Code, Qoder и OpenCode через независимые адаптеры с поддержкой версий и обеспечивает:

- установлено обнаружение и проверка навыков;
- официальная коллекция Hook/плагинов в реальном времени плюс помеченный резервный сеанс сеанса;
- Активация навыков, загрузка ресурсов и сроки вызова инструментов;
- отношения субагента, MCP, файла и артефакта;
- продолжительность, токен, ошибка, повтор и сводка состояния, если таковая имеется;
- Runtime Overview и первая пограничная диагностика;
- панорама DAG, временная шкала событий и инспектор доказательств;
- сравнение возможностей одного и того же агента и между агентами;
- отдельная поверхность Inferred Analysis, которая не может перезаписывать факты времени выполнения;
- возможность экспорта OTLP/HTTP и поддерживаемый импорт трассировки наблюдения.

MVP **не** включает в себя торговую площадку, универсальную среду выполнения агента, обеспечение безопасности, управление предприятием или претензии о причинно-следственных связях.

## Детальная установка

Для кратчайшего поддерживаемого пути используйте однострочный установщик выпуска в [Быстрый старт](#quick-start). Полный процесс первого запуска, этапы перезапуска/доверия для конкретного агента, поведение конфиденциальности и устранение неполадок находятся в [Руководство по началу работы](docs/getting-started.md).

Для разработки базовая реализация не имеет зависимостей времени выполнения, выходящих за пределы Python 3.9+. Из корня репозитория:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/skill-runtime install --enable-hooks
.venv/bin/skill-runtime start
```

Затем откройте [http://127.0.0.1:4317](http://127.0.0.1:4317).

Одноразовая команда `install`:

1. сканирует расположение навыков пользователя, проекта и кэшированного плагина;
2. обнаруживает Codex, Claude Code, Qoder и OpenCode без изменения их конфигурации;
3. показывает, какие пути агента и навыка будут считываться;
4. загружает собственный отправитель с низким уровнем запуска с проверкой контрольной суммы для текущей платформы, возвращается к локальной сборке C и, наконец, отправителю Python, и предварительно нагревает новый собственный двоичный файл один раз во время установки;
5. создает `~/.skill-runtime/config.json` и локальный индекс SQLite.

При интерактивном запуске он запрашивает один раз перед добавлением перехватчиков агента, открывающихся при сбое. `--no-hooks` сохраняет импорт расшифровок как помеченный резервный вариант, а `--enable-hooks` записывает явное согласие и устанавливает только управляемые записи. Для Codex откройте `/hooks` после установки, просмотрите точные управляемые команды и доверьтесь им. Codex намеренно требует этой явной проверки перехватчиков, добавленных вне управляемой конфигурации предприятия. Запустите новую задачу/сеанс Codex после доверия к Hook, затем запустите:

```bash
.venv/bin/skill-runtime doctor
```

Qoder загружает конфигурацию Hook при запуске, поэтому перезапустите Qoder после первой установки. OpenCode обнаруживает управляемый плагин только для наблюдения из своего глобального каталога плагинов; перезапустите OpenCode, если текущий процесс предшествует установке. Ни одна из интеграций не читает и не изменяет запросы модели.

Интеграция становится **действующей** только после того, как база данных получит реальное событие `official_hook`. Простое написание `~/.codex/hooks.json` отображается как **Ожидание**, а не как Соединение. `start` запускает Collector, средство наблюдения за резервной расшифровкой, обработчик хранения, хранилище SQLite и запускает UI в качестве управляемого фонового процесса. Никакой запрос модели не пересылается.

Команды жизненного цикла:

```bash
skill-runtime status
skill-runtime doctor
skill-runtime restart
skill-runtime stop
skill-runtime config --set retention_days=30
skill-runtime config --set network_export.endpoint=https://collector.example/v1/traces
skill-runtime config --set network_export.enabled=true
skill-runtime uninstall --keep-data
```

`uninstall` удаляет только управляемые записи Hook и файлы, принадлежащие Skill Runtime. Без `--keep-data` требуется интерактивное подтверждение (или `--yes`) перед удалением `~/.skill-runtime`; Сеансы агентов и источники навыков никогда не удаляются.

Чтобы индексировать и обслуживать отдельно:

```bash
PYTHONPATH=src python3 -m skill_runtime_intelligence index
PYTHONPATH=src python3 -m skill_runtime_intelligence serve
```

Импортируйте существующий экспорт трассировки из основной системы наблюдения:

```bash
PYTHONPATH=src python3 -m skill_runtime_intelligence import \
  ./trace-export.json \
  --format auto
```

Версионные профили импорта в настоящее время распознают формы OTLP/Phoenix, Langfuse, LangSmith, W&B Weave и Datadog JSON. Они создают SkillRun только тогда, когда источник содержит явную семантику Навыка; общие имена диапазонов не рассматриваются как свидетельство активации.

Экспортируйте нормализованные доказательства времени выполнения, специфичные для навыков, в любую конечную точку трассировки OTLP/HTTP:

```bash
.venv/bin/skill-runtime start \
  --otlp-endpoint https://collector.example/v1/traces \
  --otlp-header Authorization='Bearer …'
```

Экспорт отключен, если конечная точка не настроена явно. Контрольные точки, статус повторной попытки и работоспособность места назначения отображаются в настройках. Необработанные подсказки, полезные данные инструментов, учетные данные и содержимое ресурсов навыков не экспортируются. Для фонового экспорта с проверкой подлинности укажите стандартный `OTEL_EXPORTER_OTLP_HEADERS` в среде перед `skill-runtime start`; заголовки никогда не записываются в конфигурацию Skill Runtime или аргументы процесса.

## Отправка живых доказательств во время выполнения

`skill-runtime start` включает локальный сборщик. Собственные адаптеры телеметрии, официальные перехватчики, облегченные перехватчики при отказе и интеграции SDK могут добавлять одно событие или ограниченный пакет в `POST /api/events`:

```bash
curl -X POST http://127.0.0.1:4317/api/events \
  -H 'Content-Type: application/json' \
  -d '{
    "event_id": "evt-example-activation",
    "event_type": "skill.activated",
    "occurred_at": "2026-07-29T05:00:00Z",
    "session_id": "agent-session-example",
    "turn_id": "turn-1",
    "activation_mode": "explicit_tool",
    "skill": {"name": "pdf"},
    "source": {
      "adapter": "example-agent",
      "adapter_version": "1.0",
      "collection_mode": "official_hook",
      "source_event_id": "source-event-1"
    },
    "evidence": {
      "grade": "observed",
      "confidence": 1.0,
      "basis": "Official runtime hook"
    },
    "payload": {"tool_name": "Skill"}
  }'
```

Конечная точка редактирует общие учетные данные перед сохранением, выполняет дедупликацию с помощью `event_id`, сохраняет отдельный отредактированный необработанный конверт и возвращает результирующий `skill_run_ids`. `GET /api/collector/schema` предоставляет поддерживаемый словарь событий и режимы сбора. UI прослушивает `/api/stream`, используя SSE, с опросом только в качестве резервного варианта повторного подключения.

Индикатор источника отличает первичные данные времени выполнения от `Transcript fallback` и импортированных трассировок. Конечная точка сборщика сама по себе не требует встроенной телеметрии: каждый производитель должен указать, пришло ли его событие из встроенной телеметрии, официального перехватчика, упрощенного перехватчика или SDK.

### Дополнительные крючки агента

Сначала проверьте точные пути и события. Эта команда доступна только для чтения:

```bash
.venv/bin/skill-runtime setup
```

Для установки Hook требуется явный флаг:

```bash
.venv/bin/skill-runtime setup --enable-codex-hooks
.venv/bin/skill-runtime setup --enable-claude-hooks
```

Установщик создает резервную копию конфигурации агента, сохраняет существующие перехватчики и добавляет только записи, имеющие маркер управления Skill Runtime. Адаптер перехватчика хранит минимальные поля жизненного цикла, а не полные подсказки или полезные данные инструмента. Для завершенных вызовов инструмента он извлекает в памяти только точный `SKILL.md`, стандартный ресурс Skill и пути к измененным файлам; необработанные команды, тела патчей, подсказки и выходные данные инструментов отбрасываются перед сохранением. Пока среда выполнения активна, сокет Unix с ограниченными разрешениями является быстрым путем; дополнительный собственный отправитель позволяет избежать запуска Python. Когда среда выполнения не активна, автономный путь открытия при сбое добавляет отредактированные доказательства в `~/.skill-runtime/queue/events.jsonl`. `skill-runtime start` воспроизводит эту очередь с дедупликацией идентификатора события.

События Codex используют свои официальные Hook API (`SessionStart`, `SessionEnd`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PreCompact`, `PostCompact`, `SubagentStart`, `SubagentStop` и `Stop`). Codex в настоящее время выполняет командные перехватчики синхронно, поэтому Skill Runtime использует локальный сокет Unix/собственный отправитель с ограниченным временем ожидания. Любая ошибка доставки игнорируется и ставится в очередь; это никогда не меняет решения Агента. См. [официальная документация Codex Hook](https://developers.openai.com/codex/config-advanced#hooks).

Удалите только управляемые записи с помощью:

```bash
.venv/bin/skill-runtime setup --remove-codex-hooks
.venv/bin/skill-runtime setup --remove-claude-hooks
```

По умолчанию сервер привязывается к `127.0.0.1`. Полная расшифровка сообщений и полезные данные инструмента не копируются в индекс. Общие секретные шаблоны редактируются перед сохранением нормализованных сводок.

Запустите набор тестов без зависимостей с помощью:

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

## Разработка релиза

GitHub Actions запускает тесты Python 3.9–3.13, проверку JavaScript, собственную компиляцию отправителя и реальный дым-тест установки/запуска/доктора/остановки/удаления. Тег `v*` создает пакеты Wheel/sdist, а также собственные отправители Linux и macOS, защищенные контрольной суммой. Установщик CLI загружает соответствующий ресурс выпуска, поэтому конечным пользователям не нужен компилятор.

Запустите первый эксперимент по диагностике, связанной с продуктом:

```bash
python3 experiments/runtime_diagnostics/run_benchmark.py
```

Он выявляет пробелы в доказательствах жизненного цикла, явные сбои, неполные прогоны и непроверенные результаты, а затем оценивает тот же механизм детерминированной диагностики, который используется API и UI. См. [План эксперимента PAI-DSW](docs/pai-dsw-experiment-plan.md) для получения информации о схеме эксперимента, тестах на отсутствие помех и контракте на воспроизводимость.

После создания колеса запустите изолированный упакованный дым жизненного цикла с помощью:

```bash
PYTHONPATH=src python3 experiments/product_lifecycle/run_benchmark.py
```

Он устанавливается во временную виртуальную среду и временный дом, выполняет полный локальный жизненный цикл без включения перехватчиков и проверяет отсутствие вмешательства в конфигурацию проекта и агента.

## Дизайн продукта, основанный на экспериментах

Поведение продукта ограничено [философия продукта, основанная на экспериментах](docs/experiment-driven-product-philosophy.md): доказательства прежде выводов, первая наблюдаемая граница перед серьезностью, типизированные отношения перед плоскими журналами и детерминированная реконструкция перед вероятностной помощью.

Текущие воспроизводимые местные данные включают:

- Пройдено 7/7 ворот локального эксперимента;
- 2400/2400 событий коллектора принимаются без мутации ввода/вывода;
- 14/14 детерминистических диагнозов корпуса ошибок без необоснованных причинных утверждений;
- представление реляционного диагноза с точностью 13/14 и F1 0,963, тогда как плоский поиск жизненного цикла достигал точности 1/14 и F1 0,080;
- В 11 случаях из 11 материалов исследования на первое место ставится самая ранняя наблюдаемая граница.

Эти результаты подтверждают механизмы и выбор представления, а не обобщение развертывания или человеческую пользу. Реальные исследования второго агента, межплатформенная задержка хвоста, калибровка реальных ошибок и исследования диагностики участников остаются открытыми пробелами в доказательствах.

Направление исследований также основано на смежных первичных работах: [SkillsBench](https://arxiv.org/abs/2602.12670) и [SWE-Skills-Bench](https://arxiv.org/abs/2603.15401) мотивируют диагноз, поскольку эффекты Навыка варьируются и могут регрессировать; [Harness-Bench](https://arxiv.org/abs/2605.27922) мотивирует межагентное сравнение с учетом возможностей; а [обследование происхождения исполнения](https://arxiv.org/abs/2606.04990) мотивирует отношения типизированных доказательств, отслеживание происхождения и инфраструктуру аудита с учетом конфиденциальности.

## Статус проекта

Версия `v0.2.0` опубликована. Среда выполнения включает в себя инвентаризацию установленных определений, официальные адаптеры Hook на основе согласия для Codex, Claude Code и Qoder, плагин OpenCode только для наблюдения, помеченный запасной вариант расшифровки, атрибуцию активной области, точные пути к файлам/артефактам, редактирование, отдельные уровни источника/связей/вывода, Хранение SQLite, сохранение, детерминированная диагностика, UI в реальном времени и сравнение между прогонами/межагентами. Экспорт OTLP/Phoenix, Langfuse, LangSmith, W&B Weave и Datadog можно импортировать; нормализованные доказательства можно экспортировать в реальном времени посредством подписки OTLP/HTTP.

Открытие кандидатов внутри модели, внутренние причины выбора модели, семантическая эффективность и утверждения о причинно-следственных связях остаются явно неподтвержденными, если источник или контролируемый эксперимент не предоставит такие доказательства.
