Agent Skill Runtime Intelligence— это доступная только для чтения система подтверждения и диагностики навыков агента во время выполнения. Он объединяет определения навыков, официальные события времени выполнения агента, импортированные трассировки, резервный сеанс сеанса и наблюдаемые результаты рабочей области в доказательную базу данных.Skill Run Panorama.

![Skill Run Panorama](docs/assets/skill-run-panorama.png)

## Быстрый старт

Установите последнюю автономную версию для macOS или Linux:

```bash
curl -LsSf https://raw.githubusercontent.com/hellogxp/skill-runtime-intelligence/main/scripts/install.sh | sh -s -- --start
```

Или запустите непосредственно из исходного кода:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/skill-runtime install --enable-hooks
.venv/bin/skill-runtime start
```

Открыть[http://127.0.0.1:4317](http://127.0.0.1:4317). ДляCodex, просмотрите и доверьтесь управляемым командам в`/hooks`, начните один новый ход агента, затем проверьте:

```bash
.venv/bin/skill-runtime doctor
```

Интеграция становится **Проверенной** только после получения реального официального события подключения. Настроенный перехват отображается как **Ожидание**, а не как активное свидетельство.

| Поверхность продукта | Что это отвечает |
|---|---|
| Обзор среды выполнения | КоторыйSkillRunsнужно внимание? |
| Первая наблюдаемая граница | Где доказательства впервые пропали или оказались недействительными? |
| Skill Run Panorama | Как связаны запрос, активация, ресурсы, инструменты, артефакты и результат? |
| Инспектор по доказательствам | Какой источник, класс, основа и возможности адаптера подтверждают это утверждение? |
| Сравнивать | Является ли разница поведенческой или только наблюдаемой? |
| Настройки/Доктор | Что читается, сохраняется, экспортируется, ожидает и проверяется? |

## Проблема

Установка навыка не доказывает, что агент обнаружил его. Обнаружение не доказывает активацию. Активация не доказывает, что были загружены полные инструкции и ресурсы. Исполнение не доказывает, что Навык улучшил результат.

Сегодня эти неудачи часто замалчиваются. Разработчикам остается спросить:

- Был ли навык доступен этому агенту?
- Активировалось ли оно по этому запросу?
- Какие инструкции, ссылки, сценарии и ресурсы были загружены?
- Какие инструменты,MCPбыли задействованы вызовы, субагенты, файлы и артефакты?
- Где произошел сбой выполнения, повторная попытка или потеря контекста?
- Помог ли Навык или он только увеличил стоимость и задержку?

## Направление продукта

Первый продукт — **Skill Run Panorama**:

```text
User request
    ↓
Skills discovered
    ↓
Skill selected / not selected
    ↓
SKILL.md activated
    ↓
References and scripts loaded
    ↓
Tools / MCP / subagents executed
    ↓
Files and artifacts produced
    ↓
Observable outcome
```

Панорама строится на основе реальных сигналов, а не самоотчета модели:

| Источник | Примеры | Доказательство |
|---|---|---|
| Файлы навыков | метаданные, инструкции, сценарии, ссылки, ресурсы | Наблюдается |
| События времени выполнения | Вызовы навыков, вызовы инструментов, субагенты, сбои, продолжительность | Наблюдается |
| Стенограммы сеансов | подсказки, сообщения, ввод и вывод инструментов, заказ | Наблюдается |
| Результаты рабочего пространства | изменения файлов,Gitразличия, отчеты, сгенерированные артефакты | Наблюдается |
| Корреляция | отношения между событиями, ресурсами и результатами | Производное или предполагаемое |

## Доказательная дисциплина

UIникогда не должен представлять вывод как факт времени выполнения:

- **Наблюдается** — явно присутствует в исходном событии или файле.
- **Производное** — детерминировано связанное с наблюдаемыми данными.
- **Предполагаемое** — правдоподобное объяснение с неопределенностью.
- **Экспериментальный** — эффект, измеренный посредством контролируемой парной оценки.

Одна трассировка может поддерживать атрибуцию выполнения. Он не может доказать причинную эффективность. Заявления типа «этот навык улучшил вероятность успеха» требуют повторной оценки с использованием навыка или без него.

## Принципы продукта

- По умолчанию частный, с локальным, гибридным и групповым развертыванием.
- Наблюдение только для чтения; никогда не берите на себя цикл агента.
- Никакого модельного прокси и обязательного облачного сервиса.
- В продукте по умолчанию нет блокировки, шлюза утверждения или применения политик.
- Явное происхождение и классификация доказательств.
- Постепенное раскрытие: сначала простое повествование, необработанные события по запросу.
- Поддержка изменения форматов расшифровок агентов на основе адаптера.

## Детальная установка

Базовая реализация не имеет никаких зависимостей времени выполнения, кромеPython3,9+. Из корня репозитория:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/skill-runtime install --enable-hooks
.venv/bin/skill-runtime start
```

Затем откройте[http://127.0.0.1:4317](http://127.0.0.1:4317).

Одноразовый`install`команда:

1. сканирует расположение навыков пользователя, проекта и кэшированного плагина;
2. обнаруживаетCodexиClaude Codeбез изменения их конфигурации;
3. показывает, какие пути агента и навыка будут считываться;
4. загружает проверенный контрольной суммой собственный отправитель с низким уровнем запуска для текущей платформы, возвращается к локальной сборке C и, наконец, кPythonотправитель и предварительно нагревает новый собственный двоичный файл один раз во время установки;
5. создает`~/.skill-runtime/config.json`и местныеSQLiteиндекс.

При интерактивном запуске он запрашивает один раз перед добавлением перехватчиков агента, открывающихся при сбое.`--no-hooks`сохраняет импорт стенограммы как помеченный запасной вариант, в то время как`--enable-hooks`записывает явное согласие и устанавливает только управляемые записи. ДляCodex, открыть`/hooks`после установки просмотрите точные управляемые команды и доверяйте им.Codexнамеренно требует этой явной проверки ловушек, добавленных за пределами управляемой конфигурации предприятия. Начните новый ход агента, затем запустите:

```bash
.venv/bin/skill-runtime doctor
```

Интеграция становится **живой** только после того, как база данных получит реальный`official_hook`событие. Просто пишу`~/.codex/hooks.json`отображается как **Ожидание**, никогда не подключается.`start`запускает сборщик, средство отслеживания резервных копий, средство хранения,SQLiteхрани и живиUIкак управляемый фоновый процесс. Никакой запрос модели не пересылается.

Команды жизненного цикла:

```bash
skill-runtime status
skill-runtime doctor
skill-runtime restart
skill-runtime stop
skill-runtime config --set retention_days=30
skill-runtime config --set network_export.endpoint=https://collector.example/v1/traces
skill-runtime config --set network_export.enabled=true
skill-runtime uninstall --keep-data
```

`uninstall`удаляет только управляемые записи перехватчиков иSkill Runtime- принадлежащие файлы. Без`--keep-data`, требуется интерактивное подтверждение (или`--yes`) перед удалением`~/.skill-runtime`; Сеансы агентов и источники навыков никогда не удаляются.

Чтобы индексировать и обслуживать отдельно:

```bash
PYTHONPATH=src python3 -m skill_runtime_intelligence index
PYTHONPATH=src python3 -m skill_runtime_intelligence serve
```

Импортируйте существующий экспорт трассировки из основной системы наблюдения:

```bash
PYTHONPATH=src python3 -m skill_runtime_intelligence import \
  ./trace-export.json \
  --format auto
```

Версионные профили импорта в настоящее время распознают OTLP/Phoenix,Langfuse,LangSmith,W&B Weave, иDatadog JSONформы. Они лишь создаютSkillRunкогда источник содержит явную семантику Навыка; общие имена диапазонов не рассматриваются как свидетельство активации.

Экспортируйте нормализованные доказательства времени выполнения, специфичные для навыков, в любойOTLP/HTTPконечная точка трассировки:

```bash
.venv/bin/skill-runtime start \
  --otlp-endpoint https://collector.example/v1/traces \
  --otlp-header Authorization='Bearer …'
```

Экспорт отключен, если конечная точка не настроена явно. Контрольные точки, статус повторной попытки и работоспособность места назначения отображаются в настройках. Необработанные подсказки, полезные данные инструментов, учетные данные и содержимое ресурсов навыков не экспортируются. Для аутентифицированного фонового экспорта укажите стандартный`OTEL_EXPORTER_OTLP_HEADERS`в окружающей среде раньше`skill-runtime start`; заголовки никогда не записываютсяSkill Runtimeаргументы конфигурации или процесса.

## Отправка живых доказательств во время выполнения

`skill-runtime start`включает в себя локальный коллектор. Собственные адаптеры телеметрии, официальные перехватчики, облегченные перехватчики при отказе иSDKинтеграции могут добавлять одно событие или ограниченный пакет в`POST /api/events`:

```bash
curl -X POST http://127.0.0.1:4317/api/events \
  -H 'Content-Type: application/json' \
  -d '{
    "event_id": "evt-example-activation",
    "event_type": "skill.activated",
    "occurred_at": "2026-07-29T05:00:00Z",
    "session_id": "agent-session-example",
    "turn_id": "turn-1",
    "activation_mode": "explicit_tool",
    "skill": {"name": "pdf"},
    "source": {
      "adapter": "example-agent",
      "adapter_version": "1.0",
      "collection_mode": "official_hook",
      "source_event_id": "source-event-1"
    },
    "evidence": {
      "grade": "observed",
      "confidence": 1.0,
      "basis": "Official runtime hook"
    },
    "payload": {"tool_name": "Skill"}
  }'
```

Конечная точка редактирует общие учетные данные перед сохранением, выполняет дедупликацию путем`event_id`, сохраняет отдельный отредактированный необработанный конверт и возвращает полученный результат`skill_run_ids`.`GET /api/collector/schema`предоставляет поддерживаемый словарь событий и режимы сбора.UIслушает`/api/stream`использование SSE с опросом только в качестве резервного варианта повторного подключения.

Индикатор источника отличает первичные данные времени выполнения от`Transcript fallback`и импортированные следы. Конечная точка сборщика сама по себе не требует встроенной телеметрии: каждый производитель должен указать, пришло ли его событие из встроенной телеметрии, официального перехватчика, упрощенного перехватчика илиSDK.

### Дополнительные крючки агента

Сначала проверьте точные пути и события. Эта команда доступна только для чтения:

```bash
.venv/bin/skill-runtime setup
```

Для установки перехватчика требуется явный флаг:

```bash
.venv/bin/skill-runtime setup --enable-codex-hooks
.venv/bin/skill-runtime setup --enable-claude-hooks
```

Установщик создает резервную копию конфигурации агента, сохраняет существующие перехватчики и добавляет только записи, содержащиеSkill Runtimeмаркер управления. Адаптер перехватчика хранит минимальные поля жизненного цикла, а не полные подсказки или полезные данные инструмента. Пока среда выполнения активна, среда с ограниченными разрешениямиUnixсокет — быстрый путь; дополнительный собственный отправитель избегаетPythonзапускать. Когда среда выполнения неактивна, автономный путь открытия при сбое добавляет отредактированные доказательства в`~/.skill-runtime/queue/events.jsonl`.`skill-runtime start`воспроизводит эту очередь с дедупликацией идентификатора события.

Codexсобытия используют свой официальный крючокAPI(`SessionStart`,`SessionEnd`,`UserPromptSubmit`,`PreToolUse`,`PostToolUse`,`PreCompact`,`PostCompact`,`SubagentStart`,`SubagentStop`, и`Stop`).Codexв настоящее время выполняет командные перехватчики синхронно, поэтомуSkill Runtimeиспользует местныйUnixсокет/собственный отправитель с ограниченным таймаутом. Любая ошибка доставки игнорируется и ставится в очередь; это никогда не меняет решения Агента. См.[официальная документация Codex Hook](https://developers.openai.com/codex/config-advanced#hooks).

Удалите только управляемые записи с помощью:

```bash
.venv/bin/skill-runtime setup --remove-codex-hooks
.venv/bin/skill-runtime setup --remove-claude-hooks
```

Сервер привязывается к`127.0.0.1`по умолчанию. Полная расшифровка сообщений и полезные данные инструмента не копируются в индекс. Общие секретные шаблоны редактируются перед сохранением нормализованных сводок.

Запустите набор тестов без зависимостей с помощью:

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

А`v*`tag собирает пакеты Wheel/sdist, а также собственные отправители Linux и macOS, защищенные контрольной суммой. Он выявляет пробелы в доказательствах жизненного цикла, явные сбои, неполные прогоны и непроверенные результаты, а затем оценивает тот же механизм детерминированной диагностики, который используетсяAPIиUI. См.[План эксперимента PAI-DSW](docs/pai-dsw-experiment-plan.md)для лестницы эксперимента, испытаний на отсутствие помех и контракта на воспроизводимость.

После создания колеса запустите изолированный упакованный дым жизненного цикла с помощью:

```bash
PYTHONPATH=src python3 experiments/product_lifecycle/run_benchmark.py
```

Он устанавливается во временную виртуальную среду и временный дом, выполняет полный локальный жизненный цикл без включения перехватчиков и проверяет отсутствие вмешательства в конфигурацию проекта и агента.

## Дизайн продукта, основанный на экспериментах

Поведение продукта ограничено[философия продукта, основанная на экспериментах](docs/experiment-driven-product-philosophy.md): доказательства перед выводами, первая наблюдаемая граница перед серьезностью, типизированные отношения перед плоскими бревнами и детерминистическая реконструкция перед вероятностной помощью.

Текущие воспроизводимые местные данные включают:

- Пройдено 7/7 ворот локального эксперимента;
- 2400/2400 событий коллектора принимаются без мутации ввода/вывода;
- 14/14 детерминистических диагнозов корпуса ошибок без необоснованных причинных утверждений;
- представление реляционного диагноза с точностью 13/14 и F1 0,963, тогда как плоский поиск жизненного цикла достигал точности 1/14 и F1 0,080;
- В 11 случаях из 11 материалов исследования на первое место ставится самая ранняя наблюдаемая граница.

Эти результаты подтверждают механизмы и выбор представления, а не обобщение развертывания или человеческую пользу. Реальные исследования второго агента, межплатформенная задержка хвоста, калибровка реальных ошибок и исследования диагностики участников остаются открытыми пробелами в доказательствах.

Направление исследований базируется также на смежных первичных работах:[SkillsBench](https://arxiv.org/abs/2602.12670)и[SWE-Skills-Bench](https://arxiv.org/abs/2603.15401)мотивировать диагностику, поскольку эффекты Навыка различаются и могут регрессировать;[Harness-Bench](https://arxiv.org/abs/2605.27922)мотивирует межагентное сравнение с учетом возможностей; и[обследование происхождения исполнения](https://arxiv.org/abs/2606.04990)мотивирует отношения типизированных доказательств, отслеживание происхождения и инфраструктуру аудита с учетом конфиденциальности.

## Дорожная карта

1. **v0.1 — Доказательства и диагностика во время выполнения:** живая коллекция,Skill Run Panorama, первичная диагностика, проверка доказательств, сравнение и совместимость OTLP.
2. **v0.2 — Широта адаптера и диагностические исследования:** дополнительные агенты, реальные эксперименты с использованием разных агентов и оценка участников.
3. **v0.3 — Оценка эффекта:** контролируемая парная оценка с навыком/без навыка, отделенная от однократной диагностики.

## Статус проекта

АSkillRun-первая среда выполнения доступна для запуска: инвентаризация установленных определений,Codexрезервный вариант расшифровки, на основе согласияCodexиClaude Codeадаптеры официальных перехватчиков, атрибуция активной области, точные пути к файлам/артефактам, редактирование, отдельные уровни источника/связей/вывода,SQLiteхранение, хранение, перекрестное и межагентное сравнение, детерминированная диагностика и живая панорама.UI. ОТЛП/Phoenix,Langfuse,LangSmith,W&B Weave, иDatadogэкспорт может быть импортирован; нормализованные доказательства можно экспортировать в реальном времени по согласиюOTLP/HTTP. Текущий воспроизводимый набор имеет семь проходных экспериментальных ворот. Открытие кандидатов, внутренние причины выбора модели, семантическая эффективность и утверждения о причинно-следственных связях остаются явно неподтвержденными.
