# Skill Runtime Intelligence v0.3.0

This release turns a Skill definition into an inspectable runtime contract.
For each SkillRun, the UI now shows which checkable instructions were
satisfied, which expected behaviors need review, where the first observable
deviation appears, and the evidence behind that judgment.

## Highlights

- **Skill behavior check** — extracts only explicit, checkable tool, resource,
  command, prohibition, and verification constraints from the current
  `SKILL.md`. Conditional or redacted rules remain `not_evaluable`; they are
  never invented as failures.
- **What actually happened** — names the instructions, resources, tool calls,
  files, artifacts, and agent-reported outcomes represented by stage counts.
- **Evidence-bounded assessment** — keeps runtime failure, outcome
  verification, Skill conformance, and adapter coverage separate.
- **Systemic coverage diagnosis** — a shared activation blind spot is shown as
  an adapter limitation rather than hundreds of apparent Skill failures.
- **Faster run index** — lifecycle summaries for the latest runs are computed
  in one batched query.

## Evidence discipline

The release preserves the project's core boundary: one run can establish what
was observed and how evidence was deterministically connected, but it cannot
prove that a Skill caused the final outcome. `Observed`, `Derived`, `Inferred`,
and `Experimental` remain distinct, and diagnostic causal scope is reported
separately from evidence certainty.

## Upgrade

Existing v0.2 installations can use the standard installer:

```bash
curl -LsSf https://raw.githubusercontent.com/hellogxp/skill-runtime-intelligence/main/scripts/install.sh | sh -s -- --start
```

Existing local data is migrated in place. Source Agent sessions and Skill files
are never modified by the migration.

## Known limits

- Candidate discovery and model-internal Skill selection reasons remain
  unavailable unless the Agent exposes them.
- A reported outcome is not independently verified unless a deterministic
  verifier or explicit evaluation record is present.
- Cross-Agent behavioral comparison requires aligned tasks, Skill definitions,
  adapter capabilities, and compatible time provenance.

See the [Getting Started guide](../getting-started.md) and
[adapter capability matrix](../adapter-capability-matrix.md) for setup
and source-specific limitations.
